# Публикация статей в Yotti Blog

## 1. Выберите язык

- Русская статья создаётся по `templates/article-ru.md` и получает
  `language: "ru"`.
- Английская статья создаётся отдельно по `templates/article-en.md` и получает
  `language: "en"`.
- Английская версия не создаётся автоматически из русской.

## 2. Создайте черновик

1. Скопируйте подходящий шаблон в папку `articles`.
2. Назовите файл латинскими буквами, например `esim-in-japan-2026.md`.
3. Заполните заголовок, постоянный `slug`, описание, дату, автора и категории.
4. Оставьте `published: false`, пока текст не утверждён.
5. Напишите не меньше 150 слов.

`slug` нельзя менять после первого импорта: это часть постоянной ссылки источника.

Перед переключением на `published: true` обязательны `reviewer`, `reviewedAt`,
`reviewAfter` и минимум два разных HTTPS-адреса в `sources`. Без них GitHub
остановит сборку и статья не попадёт в RSS.

## 3. Добавьте категории

Первая категория — тематическая, например `Travel-tech и сервисы`. Если статья
связана со страной, добавьте отдельной строкой её ISO-код заглавными буквами:

```yaml
categories:
  - "eSIM и устройства"
  - "TR"
```

## 4. Добавьте обложку при необходимости

1. Подготовьте JPEG, PNG или WebP размером не меньше 1200×675 и пропорцией 16:9.
2. Загрузите файл в `assets/covers`.
3. Добавьте в заголовок статьи:

```yaml
cover:
  url: "https://timostas.github.io/yotti-blog-rss/assets/covers/imya-fayla.jpg"
  type: "image/jpeg"
  alt: "Краткое описание изображения"
```

## 5. Отправьте на публикацию

1. Проверьте текст, дату и язык.
2. Установите `published: true`. Для немедленной публикации задайте текущее или
   прошедшее `publishedAt`; для отложенной — будущую дату и время с часовым
   поясом.
3. Сохраните изменения в ветке `main`.
4. Дождитесь зелёного статуса `Build and publish RSS` в GitHub Actions.
5. Запустите ручную синхронизацию нужного RU- или EN-потока в Yotti либо
   дождитесь автоматической синхронизации в течение часа.
6. Проверьте карточку и полную страницу без авторизации.

## 6. Исправьте опубликованную статью

Измените существующий Markdown-файл, не меняя `slug`. После сборки повторно
синхронизируйте соответствующий поток в Yotti. Импортёр обновит прежнюю запись,
не создавая дубль.

## Отложенная публикация

GitHub Actions пересобирает потоки каждые 30 минут. Статья с `published: true`
не появится в RSS и HTML раньше `publishedAt`. После её появления Yotti заберёт
обновление при следующей часовой синхронизации. Поэтому фактическое появление на
Yotti следует планировать в окне до 90 минут после назначенного времени.
