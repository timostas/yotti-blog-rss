An eSIM QR code is activation data. Scanning it can start the download of a mobile profile, so it should not be posted, forwarded in a group chat or included in a public support screenshot. If it has already been exposed, ask the provider to inspect and, where necessary, revoke or replace it. Do not test the leaked code on a spare phone.

Provider controls differ. A download may be bound to a device, protected by a separate confirmation code or limited after an attempt. Exposure therefore does not prove either that the profile was stolen or that the image is harmless. The provider’s order state is the evidence that matters.

## A QR image performs an account action

Apple documents QR scanning as one route for adding a mobile plan to an iPhone. Windows likewise accepts an operator’s QR or manual activation code and then asks to download the eSIM profile. This is different from scanning a restaurant menu or webpage link: the information participates in provisioning a subscription.

Keep the other credentials separate. An order reference identifies the purchase, an EID identifies the embedded component, and a confirmation code may approve the download. Combining all of them in one screenshot removes useful layers of protection.

## Before installation

Open the order on a private device or in the provider account. Use the activation method named in the instructions. A second personal screen is convenient for camera scanning; recent iPhones can also recognise a provider QR inside supported email and browser flows.

After the line appears in Settings, stop using the code. Enabling the line, selecting it for data and following the roaming instruction do not require another scan. Keep the installed profile while diagnosing a later network problem.

## After an accidental share

The response depends on where the image went, but it should start immediately:

1. remove the public post or shared link where possible;
2. avoid forwarding it again, including to an ordinary support chat;
3. open the provider’s official account or verified support channel;
4. give the order reference, exposure time and current profile status without attaching the QR image.

Ask whether the activation details remain valid and whether they should be revoked. If replacement is required, use only the method supplied for that order.

A direct message to a trusted companion creates a different exposure from a public forum, yet deleting the message does not confirm that every copy has gone. Notifications, photo libraries and cloud backups may retain it. Let the provider determine the technical state instead of guessing from the chat history.

## When your own scan fails

An error has several plausible meanings. Place it before taking action.

- **The line is already listed:** installation may have completed; move to line and network checks.
- **No eSIM command exists:** confirm the exact device and regional model before using the code again.
- **The download begins and stops:** keep dependable Wi‑Fi, record the message and ask whether a confirmation code or account action is missing.
- **The provider reports the activation as consumed or invalid:** request an approved replacement rather than trying random devices.

Do not upload the image to a general QR-decoder website. The phone or computer’s eSIM settings are the intended scanner, and a third-party service creates another uncontrolled copy without installing the plan.

## Once the profile is on the device

The installed line and provider account now carry the useful evidence. Give the line a recognisable name and test data only in the covered destination, according to the plan’s validity rules. A QR code is not a reusable switch for turning service on and off.

If the device will be replaced, sold or reset, obtain the transfer or reissue path first. Erasing a working line can turn a routine change into a recovery request. If a phone is lost, secure the device and accounts before deciding when remote erasure is appropriate.

Support normally needs the order number, model, country, exact error and whether a profile is visible. Passwords, one-time login codes and banking messages should never be provided. Share the activation image only inside a provider-controlled secure flow that explicitly requires it, not in a ticket comment visible to unrelated staff or users.
